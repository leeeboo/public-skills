## 目标

回答四个问题：

1. 这堂课实际由哪些部分组成？
2. 它实际练到了什么，而不是设备把它叫什么？
3. 完成质量的最强证据是什么？
4. 下一次最值得观察或调整的一件事是什么？

单次训练只能说明当次表现，不能单独证明长期能力提升或退步。

## 内置赛博黑影儿决策链

本 Skill 不依赖外部 `shadowrunner`；下面的训练复盘版本只保留与 COROS 数据和下一步决策直接相关的部分。安全筛查始终优先于数据解释。

| 框架 | 在 COROS 复盘中的用法 |
|---|---|
| 反推前置条件 | 从原计划、实际结构和完成质量反推它依赖的训练史、恢复、环境与资源；不把一次完成结果当成通用起点。 |
| 阶段—瓶颈 | 结合用户目标和时间范围判断建立习惯、积累能力、专项准备、维持或恢复阶段；从执行、输出、生理代价、环境、恢复和数据质量中提出最多两个候选瓶颈。 |
| 适用域 | 他人方案、教练经验、研究结论和设备建议都先核对目标、训练史、环境与恢复条件；不匹配时只作为提问线索。 |
| 边际收益 | 比较“观察一个变量”“调整一次同类训练”和“寻求专业反馈”的潜在收益、恢复成本、时间成本与回滚难度；无法估算就写明未知。 |
| 长期适应 | 把单次结果当作短期反馈，不据此宣布平台期、能力上限或长期退步；需要跨活动结论时使用可比训练和足够观察窗口。 |
| 记录优先 | 保留目标、条件、预期、实际输出、生理代价、主观反馈、唯一改变的变量、停止条件，以及被支持或推翻的假设。 |

如果用户只要求还原这一次活动，不强行扩展到长期决策；只有用户问“接下来怎么办”“是否应该加量”或引用外部方案时，才展开阶段、适用域和边际收益判断。缺少安全所需信息时，不设计训练实验。

## 证据优先级

从高到低使用：

1. 活动详情与可核对的分圈数据；
2. 结构化训练段和用户提供的原计划；
3. 同一活动中可比训练段的变化；
4. 用户主观体感、可信天气、地形和补给信息；
5. 明确标注为外部上下文的 OpenWeatherMap One Call API 4.0 温湿度估计；
6. COROS 的训练标签、训练效果、能力或恢复模型；
7. 客户端或 COROS 自动生成的教练式总结。

自动总结可以帮助发现线索，但不能替代详情和分圈。发现冲突时以原始事实为准，并说明冲突。

## 第一步：还原训练结构

先按时间顺序标记：

- 热身；
- 加速跑或准备段；
- 主训练组；
- 组间恢复；
- 放松；
- 意外暂停或明显中断。

结构识别信号：

- 分圈名称或结构化 workout step；
- 配速、功率和心率的阶梯变化；
- 重复时长/距离；
- 恢复段的明显降速；
- 用户说的“15 分钟 × 2”“最后 20 分钟”等计划。

不要只按整公里自动分圈猜间歇结构。自动分圈可能切断真正的训练段；此时优先使用结构化训练段或自定义时间窗。

无法可靠拆分时写：

```text
活动详情可读，但没有足够分段信息；下面只能评价整段趋势，不能判断每组完成质量。
```

## 第二步：判断训练目的

综合用户原计划、结构和实际强度，选择一个主标签：

- 轻松 / 恢复；
- 有氧稳态；
- 渐进；
- 阈值附近；
- 间歇；
- 长距离；
- 比赛 / 测试；
- 未知。

同时判断用户目标允许推断的训练阶段：建立习惯、积累能力、专项准备、维持或恢复。单次活动不能独立确定阶段；没有目标、时间范围或近期背景时写“阶段未知”，不要把一次表现写成长期能力结论。

若使用 COROS 阈值配速、配速区间或能力评估，只能写“按当前设备估计”。设备估计不是实验室测量，也不应由一次活动反向改写。

训练同时具备两种特征时，选实际占主导的刺激，另一种写作补充。例如长距离后程持续加速可写“长距离为主，后程带稳态/渐进刺激”。

## 第三步：比较输出与代价

把指标分组，避免把一个数解释成全部：

| 维度 | 常见指标 | 能说明什么 | 不能单独说明什么 |
|---|---|---|---|
| 外部输出 | 配速、速度、功率、爬升 | 实际完成的工作 | 疲劳原因、健康状态 |
| 生理反应 | 心率、心率趋势 | 当次生理代价的一个代理 | 具体病因、恢复充分与否 |
| 动作结果 | 步频、步幅 | 动作结果如何变化 | 技术好坏、受伤原因 |
| 环境约束 | 地形、海拔、温度、停顿 | 可解释部分波动 | 不能在缺失时被臆测 |

只比较可比段：

- 相同距离或时长；
- 相同训练目的；
- 尽量相似的地形和风向；
- 排除明显暂停、交通等待和 GPS 异常。

表达变化时优先给原值和方向，例如：

```text
第二组功率基本持平、配速小幅变快，但平均心率更高。
```

这支持“相同输出的生理代价上升”，但不能单凭这一点断定原因。可能性包括热身后的心率爬升、环境、累积疲劳、补给、睡眠或测量误差；只有拿到额外证据才能排序。

### 配速的符号陷阱

配速数值越小代表越快。跨段计算百分比时优先换成速度或直接写秒/公里变化，避免把负数误写成退步。

### 心率漂移

只有在输出较稳定、训练段足够连续且环境没有明显变化时，才描述“心率—输出脱耦”或“同等输出下心率抬升”。不要把它直接称为过度训练、脱水或心脏问题。

### 步频与步幅

把变化写成观察，不写成技术处方。例如“后段速度下降主要伴随步幅缩短，步频相对稳定”。这不自动意味着应该强行加步幅或加步频。

## 第四步：判断完成质量

按训练目的选证据，不套统一评分。

### 重复训练

看：

- 每组输出是否接近计划；
- 组间波动是否逐步扩大；
- 最后一组是否靠明显提高生理代价才维持输出；
- 恢复段是否能让下一组重新稳定；
- 是否前快后崩。

优先比较第一组完整主训练与最后一组完整主训练。不要把不完整尾圈算成一组。

### 渐进跑

看输出是否有序上升，以及心率/动作代价是否同步失控。渐进不等于最后冲刺；如果只有最后很短一段突增，写“末段加速”，不要重命名整堂课。

### 轻松跑

重点是强度是否受控和过程是否顺畅，不因配速慢而扣分。若环境、爬升或疲劳信息缺失，不给“应该更快”的判断。

### 长距离

看时长、后程稳定性、明显掉速与用户主观体感。单次长距离不能证明马拉松准备完成，也不能据此承诺成绩。

### 比赛或测试

把执行复盘与能力判断分开。说明配速分配、后程变化和数据质量，但不据一次比赛给未来成绩保证。

## 第五步：定位主要问题

候选问题只从以下类别选择：

- **执行**：起步过快、组间波动、结构未完成；
- **输出稳定性**：相同目的训练段持续掉速/掉功率；
- **生理代价**：输出稳定时心率持续抬升，但原因未知；
- **动作结果**：后段步频/步幅变化与输出下降同时出现；
- **环境与路线类型**：用户用文字提供的总爬升、平路/起伏/跑道、温度、风、路况或停顿影响比较；OpenWeatherMap 只能作为标注了来源的外部上下文；
- **恢复上下文**：近期负荷、睡眠或主观疲劳可能相关；
- **数据质量**：传感器缺失、GPS 漂移、分圈不可靠。

只选择证据最强的 1 个。证据相近时并列最多 2 个，并写出区分它们需要的一个信息。

把每个候选写成“支持证据—反证或未知—置信度”，并说明它是否属于当前阶段真正要解决的瓶颈。没有证据时写“暂不能定位”，不要用人格、意志力或单个设备标签填空。

禁止从训练数据推断人格、意志力、焦虑、家庭关系或心理伤口。不要用“懒”“不够狠”“意志薄弱”等标签。

## 第六步：设计下一步

下一步应低风险、可回滚、可验证，优先顺序：

1. 下次记录主观用力感、天气或疼痛变化；
2. 使用同一分段方式，方便比较；
3. 在下一堂同类训练中观察一个指标关系；
4. 与教练核对原计划和实际目的；
5. 只有用户明确要求且信息充分时，讨论非处方性的调整方向。

每次最多设计一个变量的改变或观察，并明确：

- **只改变 / 只观察**：...
- **保持不变**：...
- **观察指标**：...
- **复盘时点**：...
- **停止条件**：出现疼痛、异常症状、持续恶化或无法安全解释数据时停止实验并转向合格专业人士。

若无法在安全边界内设计这样的行动，只整理用户应携带给教练或医疗专业人士的问题，不补充训练剂量。

不要直接给周跑量、精确配速/心率、组数、恢复天数、补给克数或药物建议。需要个体化剂量时，让用户与合格教练或医疗专业人员共同决定。

合格示例：

```text
下一次同类训练先保持分段方式一致，重点记录每组结束时的主观用力感；这样可以区分心率抬升主要是正常累积还是当天状态异常。
```

不合格示例：

```text
下周改成 6 × 1 km，配速 3:40，组间慢跑 90 秒。
```

## 常见训练类型

| 类型 | 最重要的结构证据 | 常见误判 |
|---|---|---|
| 轻松跑 | 持续、强度受控 | 因配速慢判定失败 |
| 稳态跑 | 连续且输出稳定 | 把全程平均当主训练 |
| 渐进跑 | 多段有序提速 | 末段短冲刺冒充渐进 |
| 阈值训练 | 持续或长分段、恢复较短 | 只看设备标签 |
| 短间歇 | 重复快段与恢复段清楚 | 用自动公里圈替代训练段 |
| 长距离 | 总时长与后程趋势 | 据一次活动预测比赛结果 |
| 比赛 / 测试 | 明确最大或接近最大执行 | 把比赛结果直接转成训练处方 |

## 缺失数据与置信度

### 高

活动详情、主训练分段、关键指标和用户原计划都存在，结论由至少两个独立信号支持。

### 中

详情完整但缺分圈、环境或主观体感；可以判断大方向，原因仍有多个候选。

### 低

只有整次平均、关键传感器缺失、分段错误、用户报告的路线类型变化大，或活动本身不是跑步。

始终写清最关键缺口。置信度低时减少结论数量，不靠更多形容词补洞。

## 写作规则

- 先结论，后证据；每个判断紧跟对应数据。
- 默认最多 3 条关键证据、2 个问题、1 个下一步。
- 用“数据显示”“这支持”“还不能区分”标记事实层级。
- 不重复 COROS 已显示的所有指标。
- 始终不索取或输出地点、地图、路线/GPS 截图、坐标、内部 ID、FIT 文件或下载链接；只询问“平路/起伏/跑道、总爬升、是否折返”等抽象文字特征。若启用天气补全，只呈现外部上下文，不呈现用于请求的粗略坐标。
- 不冒充教练、医生或 COROS 官方客服。
- 不用真实人物的招牌表达；“赛博黑影儿”只代表本项目的决策框架。
