# COROS 连接诊断

按层定位，不让用户重复授权，也不把“没有数据”误判成“连接失败”。

## 诊断顺序

### 1. 客户端层

确认当前客户端是否真的支持以下两件事：

- remote MCP 或现成 COROS 插件；
- 浏览器 OAuth，而不是只能填写静态 Token。

如果当前是 ChatGPT Work、ChatGPT 桌面版中的 Codex 或 Codex CLI，先检查 COROS 插件是否已安装、启用并完成底层连接：ChatGPT Work 走“插件 / Plugins → 搜索 COROS”，Codex 桌面版走“插件 → 浏览目录 / Plugins → Browse directory → 搜索 COROS”，CLI 走 `/plugins`。不要先检查 Settings → MCP servers。

如果不支持，停止配置，改用 `client-connections.md` 中的推荐客户端。不要搭建未经用户同意的本地桥接、代理或转发服务。

### 2. 工具层

检查当前会话能否看到 COROS 活动工具。

- 看不到：可能未安装、未在本会话启用、工作区禁用，或保存后未重启。
- 看得到但不可调用：进入认证层。
- 能调用但无数据：进入账号与同步层。

新连接常需要新开聊天、重新选择工具或重启客户端。只执行一次，不循环重装。

### 3. 认证层

401、403、`login required`、`authorization required` 都视为授权未完成或已过期。

处理：

1. 在客户端中选择 Reconnect / Authenticate / Login。
2. 只打开客户端提供的 COROS 官方授权页。
3. 完成后回到客户端，新开聊天做最小查询。
4. 仍失败时，先在 `https://t.coros.com` 验证 COROS 账号本身能否正常登录。

不要让用户把授权回调 URL、code、Cookie 或 Token 发过来。不要指导用户关闭账号安全保护。

### 4. 账号与同步层

调用成功但没有活动时，依次检查：

1. 手表/设备上的活动是否已经同步进 COROS App；
2. COROS App 中能否看到这条活动；
3. 授权的是否为同一个 COROS 账号；
4. 查询日期与用户所在时区是否正确；
5. 运动类型是否被错误过滤。

先查最近 14 天。用户确认训练更早时，再按其给出的日期扩展；不要默认读取完整历史。

### 5. 权限与能力层

有活动列表但缺详情、分圈或自定义时间窗时：

- 检查客户端的单工具权限是否被关闭；
- 检查会话是否启用了正确的 COROS 工具；
- 若服务器只暴露部分工具，标记 `PARTIAL` 并降级分析；
- 不把健康数据权限当作单次跑步复盘的必需条件。

### 6. 服务层

超时、5xx 或临时服务错误：

1. 保留已经取得的数据；
2. 等短时间后只重试一次相同的最小请求；
3. 仍失败则查询该客户端和 COROS 的官方状态/帮助页面；
4. 告知用户服务暂时不可用，并说明下次从哪一步继续。

不要通过提高抓取频率、换 Cookie 或绕过访问控制来处理。

## 最小验证问题

连接完成后只问：

```text
只列出我最近一条跑步的日期、距离和时长，不要显示地点。
```

成功标准：

- 返回真实活动；
- 日期、距离、时长与 COROS App 基本一致；
- 没有泄露地点、内部 ID 或下载链接；
- 不需要再次认证。

最小验证通过后，再请求详情与分圈。若摘要与 App 不一致，先排查单位、时区、暂停和活动类型，不开始训练解释。

## 给用户的状态模板

### 尚未连接

```text
我还看不到 COROS 工具。我们先完成连接；你现在只需要打开【客户端中的具体菜单】。看到后回复“完成”，不要发送账号或密码。
```

### 等待授权

```text
连接已经添加，但授权还没完成。请只在刚打开的 COROS 官方网页登录；完成后回到这里回复“已授权”，不要粘贴回调地址或验证码。
```

### 连接正常但没有活动

```text
连接本身正常，但当前日期范围没有返回跑步。这通常是同步、账号或日期范围问题，不是授权失败。请先确认这条训练已经出现在 COROS App 中。
```

### 部分能力可用

```text
我能读取活动摘要和详情，但当前客户端没有提供分圈数据。我可以做降级复盘，不过无法可靠判断间歇组间差异，置信度会降低。
```

### 服务临时错误

```text
配置和授权都已通过，失败发生在服务调用。我已做过一次最小重试；先保留当前状态，不需要重新安装或再次发送凭据。
```

## 何时停止

出现以下任一情况就停止自动排查：

- 客户端没有官方 remote MCP / OAuth 能力；
- 用户只能通过复制密码、Token 或 Cookie 才能继续；
- 需要关闭安全控制、搭建代理或修改未知全局配置；
- 用户当前界面与官方文档明显冲突；
- 连续两次相同检查都不能区分根因。

停止时给出已确认事实、一个下一步和官方帮助链接，不假装连接成功。
